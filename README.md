# Jellyfin Markdown Books

A small, low-footprint plugin for **Jellyfin 12.0** that adds Markdown (`.md`) file
support to Books libraries — indexed like any other book on the server, and readable
in the web client through the same Play button that opens EPUB/PDF books.

## What it does

**Server side** — a library resolver (`IItemResolver`) picks up `.md` files during
scans of `CollectionType.books` libraries and indexes them as `Book` items (title from
the filename, `Container = "md"`). A custom API endpoint
(`GET /MarkdownBook/{itemId}/render`) converts the file to HTML server-side with
[Markdig](https://github.com/xoofx/markdig) — tables, footnotes, and task lists
enabled; **raw HTML disabled by default** as XSS protection for multi-user servers.

**Web client** — the plugin registers a tiny client "book player"
(`window['markdownPlayer/plugin']`, priority above the built-in epub/pdf players)
that fetches the rendered HTML and shows it in a full-screen reader overlay
(scroll, Escape/PageUp/PageDown, close button). jellyfin-web is extended in memory
via the community [File Transformation](https://github.com/IAmParadox27/jellyfin-plugin-file-transformation)
plugin — no web client files are modified on disk.

### Dependency: File Transformation

The web client injection requires the **File Transformation plugin** (install from
`https://www.iamparadox.dev/jellyfin/plugins/manifest.json`). Without it, everything
else still works — Markdown books resolve, render via the API, and are downloadable —
but the in-browser reader is not injected, and the server log explains how to enable it.

### Requirements

- Jellyfin **12.0** (plugin targets `net10.0` / `targetAbi 12.0.0`)
- Only shipped dependencies: Markdig and Newtonsoft.Json (~1.2 MB on disk)

## Building & installing

The easy path — builds and produces a self-contained installable zip:

```bash
./package.sh            # -> out/MarkdownBook_12.0.0.0.zip (staged folder + README inside)
./package.sh 12.4.0     # build against a different server version
```

The zip contains one folder, `MarkdownBook_12.0.0.0/`, with the plugin dll, its
`.deps.json`, `Markdig.dll` (the only shipped dependency — Newtonsoft.Json is not
shipped: the File Transformation registration must share the server's copy) and a
`README.md` with the install steps for remote servers:

```bash
scp out/MarkdownBook_12.0.0.0.zip user@server:/tmp/
ssh user@server sudo unzip /tmp/MarkdownBook_12.0.0.0.zip -d /var/lib/jellyfin/plugins/
ssh user@server sudo chown -R jellyfin:jellyfin /var/lib/jellyfin/plugins/MarkdownBook_12.0.0.0
ssh user@server sudo systemctl restart jellyfin
```

Manual equivalent (requires the .NET 10 SDK):

```bash
dotnet publish src/Jellyfin.Plugin.MarkdownBook/Jellyfin.Plugin.MarkdownBook.csproj -c Release \
    -o out/Jellyfin.Plugin.MarkdownBook
```

Copy the publish output's `Jellyfin.Plugin.MarkdownBook.dll`, `.deps.json` and
`Markdig.dll` into the server's `plugins/` folder (same directory as the dll) and
restart Jellyfin. To build against a different server version:

```bash
dotnet publish ... -p:JellyfinVersion=12.4.0
```

## Manual verification checklist

1. **Scan** a Books library containing the files in `test-media/books/`; check
   `GET /Items?IncludeItemTypes=Book&Fields=Path,Container` returns each `.md` as
   `Type: Book` / `Container: md` with the filename (sans extension) as title.
2. **Render API**: `curl -H 'Authorization: MediaBrowser Token="<token>"' http://<server>/MarkdownBook/<itemId>/render`
   returns `text/html`; without a token → `401`. (Jellyfin 12 rejects the legacy
   `X-Emby-Token` header and, by default, `api_key` query parameters.)
   The `unsafe-html-test.md` sample must render its script/img/iframe tags literally.
3. **Script endpoint**: `curl http://<server>/MarkdownBook/web/markdown-player.js` →
   `application/x-javascript` (unauthenticated by design).
4. **Injection**: with File Transformation installed,
   `curl http://<server>/web/index.html` contains `markdown-player.js` and
   `curl http://<server>/web/config.json` is valid JSON containing `"markdownPlayer/plugin"`.
5. **Reader**: open a `.md` item in the web client → Play → the reader overlay renders
   the document (no "unsupported book type" error).

## Troubleshooting

**Plugin listed in the dashboard but never loads** (log line
`Skipping disabled plugin 0.1.0.0 of Markdown Books`): the plugin's persisted
manifest — `<plugins>/MarkdownBook/meta.json` — was written as `NotSupported`/
`Malfunctioned` by an earlier boot in which the assembly failed to load (e.g. the
plugin was copied without the required `Markdig.dll`). That status persists across
restarts even after the files are fixed, and the dashboard can still list the
folder as installed. Fix: with Jellyfin stopped, delete `meta.json` (keep the dll,
`.deps.json` and `Markdig.dll` together in the folder) and restart — the manifest is
recreated with `status: Active`, and the log will show
`Loaded plugin: Markdown Books` followed by the plugin's
`resolver registered` line.

**`.md` files not indexed**: enable "Debug logging" in the plugin settings and
rerun the Scan Media Library task; the log gains one line per claimed file
(`Markdown Books: resolved '<path>' as a Book`). If the `resolver registered` line
is absent at startup, or no claims appear for your `.md` files, check that the
library's collection type is `books`, that the `.md` files are regular files inside
the library path, and that no other resolver-type plugin claims them first.

## Configuration & scope

Admin settings (Dashboard → Plugins → Markdown Books): enable/disable web injection,
advanced Markdown extensions, raw HTML in Markdown files, debug logging.

Not handled in this version (known scope cuts, kept intentionally small): directory-of-
`.md`-files resolved as a single book, serving relative images referenced from Markdown
files, reading-progress persistence, and plugin catalog `manifest.json` publishing.
Raw HTML permission is a trust decision — do not enable it on multi-user servers.
